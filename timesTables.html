What repeats?

Why use a loop?

The calculation and output follow the same pattern. Only the multiplier changes. One loop replaces twelve almost identical blocks of code.

07 / Extension · after validation theory
What if the input is not an integer?
The core program assumes valid input. Extend it so invalid input produces a helpful message and another attempt, rather than ending with an error.
Your extension brief
  1. Accept any integer, including 0 and negative values.
  2. Reject empty input, letters and decimal input such as 2.5.
  3. Keep asking until the input converts to an integer.
  4. Then display the table once, from 1 to 12.
For this task, 2.0 is also rejected: Python’s int() does not accept that input string.
Type/conversion check: can the input become an integer? We do not need a positive-only range check because the challenge allows negative integers and zero.
Hint 1 · Algorithm
Repeat: get input → attempt conversion → on success, leave the input loop → on failure, show a message and repeat. Run the times-table loop after valid input is obtained.
Hint 2 · Python tools
Use while True, try, except ValueError and break. These introduce exception handling: responding to a failed conversion.

Predict the validation result
Choose an input string. Will int() accept it?
Validation checks whether input meets a rule; it cannot prove the user entered the number they intended.
Reveal worked validation solution
while True:
    try:
        number = int(input("Enter a whole number (negative or zero is OK): "))
        break
    except ValueError:
        print("Please enter an integer, such as -3, 0 or 2.")

for multiplier in range(1, 13):
    result = multiplier * number
    print(multiplier, "x", number, "=", result)

try attempts conversion. If it fails, except ValueError prints a message and the input loop repeats. If it succeeds, break exits that loop. The separate FOR loop then prints the table.
